# CraftArc website

A static site: no build step on the server, no framework. Open `index.html` through any web server.

Every page is generated by `tools/build_site.py`, which holds the copy and the shared parts (header, footer, three claims, solution, industry list) in one place. Edit the copy there and run `python3 tools/build_site.py`. Do not hand-edit the HTML: `check_all.sh` fails if a page differs from its source. The structure and the wording follow the CraftArc Website Guidance (Dash, 24 Nov 2026). Copy still waiting for CraftArc Approved Copy or for Dash's approval shows a visible draft badge.

```
website/
├── index.html          the homepage, in the guidance's twelve sections; the hero plays the existing video as a placeholder
├── private-equity.html Private Equity and VC: hero, claims, solution, the eight steps beside the video, proof and product screens
├── professional-services.html, financial-services.html, healthcare-life-sciences.html,
│   technology.html, manufacturing-industrial.html
│                       industry pages: the homepage structure with each sector's roles, proof "coming soon"
├── about.html          the elevator pitch and the founder note (both placeholders)
├── book-a-demo.html    the only lead form; ?industry=<value> presets the industry
├── styles.css          all styling
├── app.js              lead form, attribution and lead scoring
├── config.js           where leads go (edit before launch)
├── assets/img/         cleaned product screens (webp + png), logo, favicon
├── assets/video/       the VSL (720p), captions (VTT) and poster
└── tests/              end-to-end tests and copy lint
```

## Before you go live

Run the launch check. It says READY only when everything below is done:

```bash
python3 website/tests/launch_check.py
```


1. **Connect the lead form.** In `config.js`, set `leadEndpoint` to a URL that accepts a JSON POST: a Formspree form (`https://formspree.io/f/<id>`), a Zapier or Make webhook, a HubSpot workflow webhook, or your own API. Optionally set `leadEmail` as the fallback address. With neither set, the form tells the visitor it is not connected and logs an error, so it never drops a lead silently.
2. **Replace the drafts.** Put CraftArc Approved Copy into `tools/build_site.py` word for word (three claims, solution, eight steps, elevator pitch), and swap in Dash's approved wording for the other drafts. Remove each draft's badge and `data-placeholder` as it is approved. `launch_check.py` lists the open items by badge.
3. **Clear the flags** in `docs/Claims_Ledger.md` (Leadership Cockpit tag, Development Arc status, demo readiness, AgenticPM legal pages). Unapproved offer terms are deliberately absent from the pages and their source.
4. **Add analytics** if you want it. The page pushes `lead_submitted` (with the lead's priority) and `cta_click` events to `window.dataLayer`, so Google Tag Manager or the LinkedIn Insight Tag can pick them up.
5. **Publish a full privacy notice** and link it from the footer. The current text is a short placeholder statement.
6. **Fill the proof slot** (one result or one quote from the first client, with the client's written consent). Never name the client.
7. **Replace the video** after the revamp, and remove the "Video revamp in progress" note.
8. **Remove the `robots noindex` meta tag** from the page head in `tools/build_site.py`. It keeps the drafts out of search engines until launch.

## What a lead looks like

```json
{
  "name": "Alex Morgan", "email": "alex.morgan@examplecapital.com", "firm": "Example Capital",
  "role": "coo", "industry": "private_equity", "aum": "2to5b", "team": "10to25", "timing": "q1_2027", "framework": "yes",
  "message": "...", "consent": true,
  "email_type": "work", "fit_score": 100, "priority": "hot",
  "source": "craftarc-website", "page": "https://.../", "submitted_at": "2026-11-18T07:00:00.000Z",
  "utm_source": "linkedin", "utm_medium": "paid", "utm_campaign": "coo-q1", "li_fat_id": "...",
  "referrer": "...", "landing_page": "/?utm_source=linkedin..."
}
```

`fit_score` (0 to 100) weighs role (COO and managing partner highest), AUM ($2B to $10B highest), the timing of the next cycle (Q1 2027 highest), whether the organization has written down its standard for each leadership level, and team size. AUM is asked only when the industry is private equity, so other sectors top out at 75. Personal email domains are accepted but score 10 points lower. `priority` is `hot` at 70 or more, `warm` at 45 or more, otherwise `nurture`. Route hot leads to Dash the same day.

## Tests

Every website change follows the ordered checklist in `CLAUDE.md` at the repository root. Run its automated steps with:

```bash
bash website/tests/check_all.sh
```

Or run the pieces one by one:

```bash
node website/tests/e2e.mjs
```

```bash
python3 website/tests/copy_lint.py
```

`e2e.mjs` serves the site locally with a mock lead endpoint and runs 45 checks in Chromium. They cover page health on all nine pages, images, video and captions, the stated video length, anchors, and layouts at 390, 820 and 1366 pixels. They check the guidance's structure: the twelve homepage sections in order, the hero's type sizes and single button, the three equal claims and their module links, the solution diagram (Leadership Cockpit above, agent band below, the "Not yet live" tag), the eight steps with the video in view while scrolling, the FAQ questions, the industry order and status chips, and that every industry page reuses the homepage's claims and solution with only the role words changed. They also check that no page names the client or carries a first-client figure, that every "Book a demo" button goes to the Book a demo page, and 15 lead-form scenarios (validation, a full payload, attribution across pages, double submit, honeypot, server error and retry, network failure, keyboard use, email fallback, unconfigured form, the industry preset). `copy_lint.py` checks the site and the VSL against Dash's writing rules, the guidance's terms and "never write" list, the approved lines and the claims ledger. Results are written to `tests/e2e-results.json` and `tests/copy-lint-results.json`.

## Hosting

**Vercel works with no settings to change.** `vercel.json` at the repository root sets `outputDirectory` to `website`, so every page is served at its own address (for example `/private-equity.html`) with no rewrites. `.vercelignore` uploads only `website/` (not `docs/`, `vsl/`, the tests or this README). Push to `main`, and Vercel redeploys. In the Vercel project settings, leave Root Directory empty and the Output Directory override off, so `vercel.json` applies.

Any other static host works too (Netlify, Cloudflare Pages, GitHub Pages or S3): serve `website/` as the site root. Fonts load from Google Fonts, with a system-font fallback.
